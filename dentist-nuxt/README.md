# وب‌سایت دندانپزشکی دکتر آزاده مهرداد | Nuxt 3

یک پروژه مستقل **Nuxt 3 + TypeScript + Tailwind CSS + Nitro API + PostgreSQL**، به زبان فارسی و RTL، ساخته‌شده بر اساس درخواست و تصاویر مناسب موجود در پروژه Vue/Vite/PHP ارسالی.

## قابلیت‌های پیاده‌سازی‌شده

- سایت عمومی ریسپانسیو: خانه، خدمات پویا، درباره پزشک، تماس و مسیریابی، سؤالات متداول، سئوی فارسی و دکمه شناور رزرو در موبایل.
- فرم رزرو واقعی: انتخاب خدمت و مدت‌زمان، تقویم شمسی، دریافت ساعت‌های آزاد بر اساس برنامه هفتگی، تعطیلات، زمان‌های رزروشده و منطقه زمانی، مشخصات بیمار، تأیید و کد پیگیری تصادفی.
- جلوگیری از تداخل در **سطح PostgreSQL** با `EXCLUDE USING gist (tstzrange(...))` برای همه بازه‌های فعال. حتی دو درخواست هم‌زمان نمی‌توانند دو نوبت با زمان هم‌پوشان ثبت کنند. زمان خدمت در این محدودیت لحاظ می‌شود.
- پیگیری، لغو و تغییر نوبت با کد پیگیری و موبایل مطابق با مهلت لغو تعیین‌شده در پنل.
- پنل مدیریت: احراز هویت رمز هش‌شده با bcrypt، نشست پایگاه‌داده‌ای با کوکی `HttpOnly`، نرخ‌محدودسازی ورود ناموفق، آمار، فیلتر و نمای روزانه/هفتگی نوبت‌ها، وضعیت‌ها، ویرایش زمان، مدیریت خدمات، برنامه هفتگی، تعطیلات و اطلاعات سایت.
- درگاه SMS قابل اتصال به یک **سرویس‌دهنده سفارشی** و اسکریپت ارسال یادآوری برای اجرای زمان‌بندی‌شده.

> **مرزهای واقعی پروژه:** تا زمانی که PostgreSQL تنظیم و راه‌اندازی نشود، رزرو و پنل کار نمی‌کنند. پیامک تنها پس از پیکربندی و تطبیق قرارداد API با پنل پیامک شما ارسال می‌شود. پرداخت بیعانه و PWA در این نسخه فعال نشده‌اند. عکس‌های موجود، تصاویر نمونه مرتبط با دندانپزشکی هستند و تصویر واقعی پزشک محسوب نمی‌شوند. سوابق و نشانی/تلفن واقعی نیز داده نشده و باید از پنل تکمیل شوند.

## راه‌اندازی محلی

پیش‌نیاز: Node.js >=20.11، npm و Docker (یا PostgreSQL 15/16).

```bash
cp .env.example .env
# .env را ویرایش کنید و DATABASE_URL و ADMIN_EMAIL و ADMIN_PASSWORD را تنظیم کنید.
# رمز پایگاه داده داخل DATABASE_URL باید با POSTGRES_PASSWORD در docker-compose یکسان باشد.
docker compose up -d db
npm install
npm run db:setup
npm run dev
```

سایت: `http://localhost:3000`، ورود مدیریت: `http://localhost:3000/admin/login`.

برای مثال اگر در Docker از رمز `change-me` استفاده کرده‌اید، `DATABASE_URL=postgresql://dentist:change-me@localhost:5432/dentist` خواهد بود. **در محیط عملیاتی رمز قوی و منحصربه‌فرد انتخاب کنید.** مقدار نمونه `ADMIN_PASSWORD` قابل استفاده نیست؛ رمز واقعی با حداقل ۱۲ کاراکتر انتخاب کنید.

برای ساخت نسخه تولیدی:

```bash
npm run build
node .output/server/index.mjs
```

اطلاعات از دیتابیس خوانده می‌شود، نه از یک فایل mock؛ برای شروع، هشت خدمت نمونه در `database/schema.sql` ایجاد می‌شوند. اجرای مجدد راه‌اندازی، رکوردهای موجود را پاک نمی‌کند. وقتی سرویس‌های دیگری موجود باشند، هشت خدمت مجدد اضافه نمی‌شوند.

برای اجرای تست‌های یکپارچگی تقویم و جلوگیری از هم‌پوشانی دیتابیس، پس از راه‌اندازی PostgreSQL:

```bash
npm run test:core
```

این تست‌ها دیتابیس را در یک تراکنش موقت آزمایش کرده و تغییرات را `ROLLBACK` می‌کنند. پیش از انتشار عمومی، تست مرورگری end-to-end نیز توصیه می‌شود.

## تنظیم پیامک

در `.env` مقادیر زیر را برای سرویس‌دهنده خود وارد کنید:

```env
SMS_API_URL=https://sms-provider.example/api/send
SMS_API_KEY=YOUR_PROVIDER_KEY
SMS_SENDER=YOUR_SENDER_ID
```

سرویس‌دهنده باید درخواست `POST` با سربرگ `Authorization: Bearer <SMS_API_KEY>` و JSON به شکل `{ "to": "0912...", "message": "...", "sender": "..." }` را بپذیرد و پاسخ HTTP 2xx بازگرداند. **بیشتر پنل‌های پیامک ایران قرارداد متفاوتی دارند**؛ در این حالت فایل‌های `server/utils/sms.ts` و `scripts/reminders.mjs` را با مستندات سرویس خود تطبیق دهید. این API به‌صورت عمومی ناشناس نیست و نیاز به تنظیم کلید سرور دارد.

برای یادآوری نوبت‌های ۲ تا ۲۴ ساعت آینده اسکریپت زیر را هر ساعت با cron اجرا کنید:

```cron
0 * * * * cd /srv/dentist-nuxt && /usr/bin/npm run reminders >> /var/log/dentist-reminders.log 2>&1
```

توجه: در هر اجرا، پیامک موفق در دیتابیس علامت‌گذاری می‌شود تا اجرای بعدی آن را تکرار نکند. در صورت مشکل شبکه و نامشخص‌بودن دریافت پیامک توسط سرویس‌دهنده، احتمال تکرار تلاش وجود دارد و برای اطمینان کامل باید از idempotency key سرویس‌دهنده استفاده شود.

## نکات امنیتی و انتشار

1. پشت HTTPS و reverse proxy امن مستقر کنید؛ `SESSION_COOKIE_SECURE=true` و `NUXT_PUBLIC_SITE_URL=https://...` را در محیط عملیاتی تنظیم کنید.
2. بکاپ منظم و رمزنگاری‌شده دیتابیس بگیرید، دسترسی دیتابیس را خصوصی نگه دارید و رمز مدیریت را دور از مخزن ذخیره کنید.
3. فقط اطلاعات لازم برای نوبت‌دهی جمع‌آوری کنید؛ برای سیاست حریم خصوصی، نگهداری/حذف داده و انطباق با قوانین محل فعالیت مطب، متن حقوقی سفارشی تدوین شود.
4. IP واقعی فقط از reverse proxy مورداعتماد به برنامه برسد؛ در صورت نیاز rate limiting سراسری را در لایه proxy نیز اجرا کنید.
5. درگاه پرداخت بیعانه هنوز وجود ندارد و با یک فیلد رزروی غیرفعال برای توسعه آتی مشخص شده است.
6. نوبت‌های قبلی دیتابیس MariaDB پروژه قدیمی به‌طور خودکار وارد نشده‌اند؛ داده‌های منبع شامل `reserved_for = NULL` هستند و پیش از انتقال واقعی به پاک‌سازی و نگاشت زمان نیاز دارند.
7. ساعت‌های کاری پیش‌فرض نمونه‌اند: شنبه تا چهارشنبه ۹–۱۷، پنجشنبه ۹–۱۳، جمعه تعطیل. از پنل مطابق ساعات واقعی مطب تنظیم کنید.

## ساختار کد

```text
pages/                 صفحات عمومی و پنل مدیریت
components/            تقویم شمسی، کارت خدمات، منو و اجزای مشترک
layouts/               قالب سایت عمومی و قالب داشبورد
server/api/public/     API رزرو، ساعت‌های آزاد و پیگیری
server/api/admin/      API ورود، نوبت‌ها، خدمات، تعطیلات و تنظیمات
server/utils/          اتصال DB، اعتبارسنجی، رزرو و SMS
database/schema.sql    جداول + جلوگیری از تداخل + خدمات اولیه
scripts/setup.mjs      ایجاد ساختار DB و حساب مدیریت
scripts/reminders.mjs  یادآوری پیامکی با اجرای cron
public/images/         تصاویر نمایشی بهینه‌شده از پروژه ارسالی
```

## نقاط اتصال آینده

- پرداخت بیعانه: افزودن سفارش پرداخت، webhook امن و تأیید پرداخت پیش از قطعی‌سازی رزرو.
- درگاه SMS اختصاصی ایران: تطبیق آداپتر کنونی با API سرویس واقعی.
- PWA: استفاده از ماژول مناسب Nuxt و کش فایل‌های عمومی **بدون کش‌کردن داده بیمار یا پنل مدیریت**.
- ارتقای دسترس‌پذیری: بررسی نهایی روی مرورگرهای موبایل، تست صفحه‌خوان و تست مرورگر واقعی پیش از انتشار.
